Live-Demo · v1.0

Particle Playground

Ein Editor im Browser, mit dem man Partikeleffekte wie Galaxien, Feuerwerk oder Polarlichter baut, animiert und als Video exportiert. Am PC und am Handy direkt ausprobierbar.

Mein Beitrag: Eigenes Projekt – Partikel-Engine, Grafik-Renderer, Editor und Handy-Layout.

Live-Demo öffnen↗ Code
  • TypeScript
  • React
  • WebGL2
  • GLSL
  • Vitest
Was es kann
Zwölf fertige Effekte, Werkzeuge zum Anziehen, Abstoßen und Malen von Kraftfeldern, Keyframes für jeden Regler, Teilen per Link und Video-Export. Große Schwärme rechnet die Grafikkarte – wie viele Partikel flüssig laufen, hängt vom Gerät ab; eine eingebaute Leistungsanzeige zeigt die echten Werte.
Eine technische Entscheidung
Problem
Die Timeline sollte sich vor- und zurückspulen lassen, ohne dass sich der Effekt verändert.
Ansatz
Fester Zeitschritt, Zufall aus einem Seed und gespeicherte Zwischenstände – derselbe Seed ergibt immer dasselbe Bild.
Nachteil
Eingriffe mit Maus oder Mikrofon lassen sich nicht wiederholen. Solche Momente werden nicht gespeichert; beim Spulen gilt wieder der reproduzierbare Verlauf.
Ergebnis
Tests sichern ab, dass das Ergebnis bei jeder Bildrate gleich bleibt und Zurückspulen exakt denselben Zustand liefert.
Als Nächstes
Funktionen auf die Grafikkarte bringen, die bisher nur auf dem Prozessor laufen, etwa Unter-Emitter.

In Entwicklung · 3 Labore nutzbar

MedLab Studio

Eine Lernplattform für Medizintechnik: Man erzeugt zum Beispiel ein künstliches EKG, stört es mit Netzbrummen und sieht, wie Filter das Signal wieder sauber machen. Dazu kommen Labore für Reaktionszeit und für die Bedienung medizinischer Geräte. Kein Medizinprodukt – alle Signale sind synthetisch.

Mein Beitrag: Eigenes Projekt – Konzept, Architektur, Backend, Oberfläche und Tests.

Code
  • TypeScript
  • React
  • Python
  • FastAPI
  • NumPy/SciPy
  • pytest
Die drei Labore
  • EKG: Signal erzeugen, stören, filtern, Herzschläge erkennen und mit den bekannten Referenzwerten vergleichen
  • Reaktionszeit: im Browser messen, inklusive Abschätzung der Messungenauigkeit
  • Bedienung: zwei Oberflächen einer simulierten Infusionspumpe im Vergleich – welche führt zu weniger Fehlern?
Eine technische Entscheidung
Problem
Ergebnisse sollen sich später exakt wiederholen und überprüfen lassen.
Ansatz
Jedes Experiment speichert Modellversion, Parameter mit Einheiten, Seed und eine Prüfsumme des Ergebnisses.
Nachteil
Bei gemessenen Experimenten müssen die Rohdaten mitgespeichert werden, damit das Backend sie neu auswerten kann.
Ergebnis
Ein gespeichertes Experiment lässt sich jederzeit neu berechnen; die Prüfsumme zeigt, ob dasselbe herauskommt.
Als Nächstes
Ein Labor für Sensordaten von Wearables und eines für Arzneimittelspiegel im Körper.

Läuft lokal mit eigenem Backend, daher ohne öffentliche Demo. Die Startanleitung steht im README.

Fork · Experimente

Jarvis – Anpassungen und Experimente

Ein Sprachassistent im Browser von Aditya Dewaskar, der Claude Code als „Gehirn“ nutzt. Ich baue ihn zu einem deutschsprachigen Helfer für den Windows-Alltag aus.

Mein Beitrag (26 Commits), vor allem:
  • Windows-Setup und Deutsch für Spracherkennung, Stimme und Persona
  • Lokale Spracherkennung (whisper.cpp) und lokale Stimme (Piper)
  • Eine Bestätigung vor jeder Aktion, die etwas verändert
Meine Änderungen↗ Fork Original↗
  • TypeScript
  • React
  • Node.js
  • Claude Agent SDK
  • whisper.cpp
Weitere Erweiterungen
  • Ein Router, der je nach Aufgabe ein passendes Modell wählt, und ein Gedächtnis über Sitzungen hinweg
  • Kalender, Erinnerungen, Wetter, Morgenbriefing und E-Mails (nur lesend)
  • Gameserver-Verwaltung: Status und Logs frei, Befehle nur nach Bestätigung
  • Recherche und Angebotsentwürfe – Jarvis sammelt, kontaktiert aber niemanden selbst
Eine technische Entscheidung
Problem
Ein Assistent, der Befehle ausführt, darf nichts ungefragt verändern.
Ansatz
Jede verändernde Aktion braucht eine eigene Bestätigung; reine Lesebefehle laufen ohne Rückfrage.
Nachteil
Aufgaben mit vielen Schritten brauchen mehr Klicks.
Ergebnis
Kalender, Mails und Server lassen sich abfragen, ohne dass Jarvis dabei etwas ändert.

Läuft lokal mit Mikrofon und einem Claude-Code-Zugang, daher ohne öffentliche Demo.

Game Jam · v0.13

Jack’s Last Show

Ein Party-Spielmodus für nanos world: Spieler sitzen im Zirkuszelt um Jack in der Box, zufällige Events und Karten entscheiden, wer übrig bleibt. Eine Runde dauert etwa fünf Minuten.

Mein Beitrag: Eigenes Jam-Projekt – Spielidee, Server- und Client-Code, Oberfläche, Plakat, Karten und Sounds.

Code
  • Lua
  • nanos world
  • HTML/CSS/JS
  • Piper TTS
So läuft eine Show
Ein Server fasst 12 Spieler. Es gibt zwei Zirkuszelte mit je 8 Plätzen; freie Plätze besetzen Bots. Wer später dazukommt, übernimmt zur nächsten Runde einen Bot-Platz. Acht Events, Spielkarten, ein Duell als Finale, und Jack spricht 94 vertonte Sätze (Piper TTS).
Ein gelöster Fehler
Angehängte 3D-Teile von Jack sprangen in den Drehpunkt – Gesicht und Kiste fielen auseinander. Eine Diagnose im Spiel zeigte: Die Engine (nanos 1.159) hält beim Anhängen die Lage nicht ein. Seitdem setzt eine eigene Funktion die relative Lage selbst.
Als Nächstes
Stimme, Kamera und Licht im Finale feinjustieren, danach eigene 3D-Modelle über das nanos world ADK in Unreal Engine.

Läuft als Package auf einem eigenen nanos-world-Server; die Einrichtung steht im README.

Garry’s Mod · Addons

TimeTales – Addons für einen Harry-Potter-RP-Server

Für den deutschen Rollenspielserver TimeTales entwickle ich Addons, die den Schulalltag in Hogwarts spielbar machen – vom Unterricht bis zu Wahlen.

Mein Beitrag:
  • Alte Runen: ein Wahlfach mit 24 Runen, Runenpult und Werkbänken
  • Schülersprecher-Wahl: läuft jeden Monat von selbst – Kandidatur, Briefwahl, Stichwahl, Zeremonie
  • Gathering: Erzadern und Pflanzen, die nach dem Abbau nachwachsen, auch über Neustarts hinweg
  • Lua
  • Garry’s Mod
  • DarkRP
  • MySQL
Wie ich teste
Für die Wahl und die Alten Runen gibt es Testskripte, die die benötigten Garry’s-Mod-Funktionen in Lua 5.4 nachbilden. So prüfe ich Abläufe wie Fristen und Auszählung ohne laufenden Server; was dort nicht abbildbar ist, gehe ich anschließend im Spiel anhand einer Testliste durch.
Außerdem
Anpassungen an Quests, F4-Menü und Scoreboard des Servers.

Der Code gehört zum Server und bleibt deshalb privat.
